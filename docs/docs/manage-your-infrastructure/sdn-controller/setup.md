# Set up the SDN controller

<InterfaceNote>Private networks are currently created and managed from XO 5. Traffic rules moved ahead in [XO 6](../management.md#traffic-rules), with more capabilities than the XO 5 equivalent.</InterfaceNote>

This page takes you from the requirements to your first private network. If you haven't yet, read [How it works](./how-it-works.md) first: it explains the choices you'll make below.

## Requirements {#requirements}

Check these before you start: the encapsulation, the encryption and the MTU are chosen when you create a network.

### Xen Orchestra {#requirements-xo}

- The SDN controller plugin is included in **XOA Premium**.
- **Enable the plugin on only one Xen Orchestra instance.** Two controllers managing the same pools would fight over the same Open vSwitch bridges.

### Network connectivity {#connectivity}

- Xen Orchestra must reach the **management interface** of every host of the network, on TCP port `6640` (OVSDB). The management interface is the IP-enabled NIC that carries the management traffic.
- All the hosts of the network must reach one another on the **interface you select for the tunnels** (the transport interface). For a cross-pool network, this includes the hosts of the other pools.

### VxLAN {#vxlan}

If you choose the **VxLAN** encapsulation, port `4789` must be open for **UDP** traffic on all the hosts of the network. GRE has no port to open, but it must not be filtered between the hosts (IP protocol 47).

### Encryption {#encryption}

To encrypt a network, the `openvswitch-ipsec` package must be installed and running on **all** its hosts:

<Terminal shell title="on every host of the network">{`
yum install openvswitch-ipsec --enablerepo=xcp-ng-testing
systemctl enable ipsec
systemctl enable openvswitch-ipsec
systemctl start ipsec
systemctl start openvswitch-ipsec
`}</Terminal>

Due to an Open vSwitch limitation, a pool can have **at most 1 encrypted GRE network and 1 encrypted VxLAN network** at a time.

### MTU {#mtu}

GRE and VxLAN add a header to every packet (see [Encapsulation and MTU](./how-it-works.md#mtu)). Pick one of these two options before creating the network:

| Option                       | Network MTU                     | What it requires                                                                                                    |
| ---------------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Keep the default             | `1500`                          | Configure a smaller MTU (for example `1400`) on the network interface of each VM, in its operating system.           |
| Transparent for the VMs      | `1546` (GRE) or `1550` (VxLAN)  | Nothing in the VMs, but every network equipment between the hosts must carry these larger packets (jumbo frames). |

## Step 1: configure and enable the plugin {#configuration}

The plugin must be configured and loaded before you can create a private network. Like all xo-server plugins, it's configured from **Settings → Plugins** in XO 5: see [the plugin documentation](../plugins/plugins.md).

The plugin's configuration contains:

- `cert-dir`: the path of a directory containing `client-cert.pem`, `client-key.pem` and `ca-cert.pem`, used to create the TLS connections with the hosts. If none is provided, the plugin creates its own self-signed certificates.
- `override-certs`: enable to uninstall the SDN controller CA certificate already installed on the pools, and replace it with the plugin's one.

:::warning
The self-signed certificates generated by the plugin are a convenience, **neither safe nor recommended** for production: provide your own certificates with `cert-dir`. If you used the self-signed certificates before updating to XCP-ng 8.3, see [OpenSSL 3 and certificates](./advanced.md#openssl-3-sdn-upgrade-path).
:::

Once configured, load the plugin. On load, it installs its CA certificate on your pools and connects to their hosts.

## Step 2: create a private network {#network-creation}

In XO 5, go to **New → Network**, then:

1. Select a **pool**.
1. Enable **Private network**.
1. Select the **interface** on which to create the network's tunnels (the transport interface, see [the requirements](#connectivity)).
1. Give the network a **name**, and optionally a description.
1. Set the **MTU** you chose in [the requirements](#mtu).
1. Select the **encapsulation**: `GRE` or `VxLAN` (for VxLAN, see [the requirements](#vxlan)).
1. Choose whether the network is **encrypted** (see [the requirements](#encryption)).
1. Optionally, select a **preferred center**: the host to elect first as [star center](./how-it-works.md#maintenance).
1. For a cross-pool network, click **Add pool** for each other pool, and select for each one the interface on which to create its tunnels.
1. Create the network.

<UiShot light="/img/xo5/sdn-controller.png" alt="Creating a private network: interface, encapsulation, encryption, and the pools to join" url="https://your-xo/v5/#/new/network" />

The network now appears in each of its pools, and you can plug your VMs' VIFs into it like into any other network.
